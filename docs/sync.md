# Локальная синхронизация исходников

Рабочая папка: `D:\DEVELOPERS\Sites4Router`. Для Git используется отдельное зеркало `.sync-local\repository`: синхронизация не меняет рабочие исходники и не вмешивается в возможные Git-операции в рабочей папке.

После успешной публикации локальная задача Windows **RouteDeck GitHub Sync** проверяет изменения раз в минуту, когда пользователь вошёл в Windows. Файлы должны оставаться неизменными минимум 30 секунд; затем повторно проверяются их содержимое и разрешённый список. Реальная задержка обычно составляет 30–90 секунд. Компьютер должен быть включён, GitHub доступен, а локальный вход в GitHub CLI действителен.

Загрузка разрешена только для точных путей в `.sync-local\allowlist.json`. Новые файлы автоматически не добавляются. Настройки, базы, личные списки, секреты, резервные копии, журналы, профиль браузера и сборки исключаются дополнительно по имени. Распознаваемые токены и встроенные пароли останавливают загрузку; проверка не является гарантией обнаружения любого возможного секрета.

Графические ресурсы также закреплены SHA-256 в allowlist: изменение изображения требует отдельной проверки и обновления хеша. EXE не синхронизируется с исходниками; новая версия EXE публикуется отдельным релизом.

## Выключить и включить

В PowerShell:

```powershell
# Выключить
New-Item -ItemType File -Force 'D:\DEVELOPERS\Sites4Router\.sync-local\disabled'

# Включить уже настроенную задачу после проверки состояния
Remove-Item -LiteralPath 'D:\DEVELOPERS\Sites4Router\.sync-local\disabled'

# Посмотреть последнее состояние
Get-Content -LiteralPath 'D:\DEVELOPERS\Sites4Router\.sync-local\status.json'

# Полностью отключить задачу планировщика
Disable-ScheduledTask -TaskName 'RouteDeck GitHub Sync'
```

Наличие `paused.txt` означает остановку из-за изменений удалённой истории. Синхронизация не выполняет merge, reset или force-push. Сначала вручную согласуйте историю зеркала с GitHub; только после этого уберите marker `paused.txt`. Ручные незавершённые изменения в зеркале и параллельная операция Git также блокируют синхронизацию. Запуски защищены эксклюзивной блокировкой; Git сохраняет свою штатную блокировку индекса.

## Добавить новый исходный файл

1. Проверьте, что файл нужен программе и не содержит личных данных или секретов.
2. Добавьте точный относительный путь в `.sync-local\allowlist.json`, например `{"path": "services/new_module.py"}`. Используйте `/`; абсолютные пути и переходы `..` запрещены.
3. Для PNG/ICO добавьте поле `sha256` с хешем `Get-FileHash -Algorithm SHA256` после визуальной проверки.
4. Запустите `.sync-local\Check.ps1`. После успешной проверки файл попадёт в следующую синхронизацию.

Манифест, служебные скрипты, локальные credentials и журнал состояния не публикуются вместе с программой.
