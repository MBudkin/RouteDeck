# Обновления RouteDeck

Начиная с **2.4.6**, RouteDeck проверяет стабильные релизы публичного репозитория [MBudkin/RouteDeck](https://github.com/MBudkin/RouteDeck/releases). Вход в GitHub, OAuth-токен и пароль роутера для этой функции не нужны.

## Как пользоваться

1. Нажмите **Обновления** в верхней панели. При найденной новой версии кнопка подсвечивается и показывает её номер.
2. Прочитайте описание и нажмите **Скачать обновление**. Можно отменить загрузку или повторить её после сбоя.
3. Дождитесь сообщения **«Файл скачан. Размер и SHA-256 подтверждены»**.
4. В настольном Windows EXE нажмите **Обновить и перезапустить** и подтвердите действие. При работающем анализе сначала остановите его.
5. При запуске из Python или в браузере используйте **Сохранить EXE**, закройте старую программу и замените EXE вручную.

Версия 2.4.5 ещё не имеет встроенного обновления: один раз скачайте новый EXE из релиза вручную. Старый релиз остаётся доступен.

## Проверка и уведомления

Проверка запускается вскоре после открытия интерфейса и затем раз в шесть часов. Ручная проверка доступна в диалоге обновлений; запросы к GitHub выполняются не чаще одного раза в минуту. Повторные нажатия используют текущую проверку или кеш. После ограничения запросов выдерживается пауза GitHub; при отсутствии интернета остальная программа продолжает работать.

Проверяются только опубликованные стабильные релизы. Черновики, предварительные версии, неверные номера, неготовые или неоднозначные файлы не предлагаются для загрузки. Номера сравниваются численно: 2.4.10 новее 2.4.9.

## Проверка файла и установка

RouteDeck принимает только `RouteDeck.exe` из собственного репозитория по HTTPS. Перенаправления загрузки разрешены только на известные хосты GitHub. Размер ограничен; полученный EXE должен совпасть по размеру и SHA-256 с метаданными release asset GitHub. Если SHA-256 отсутствует или не совпадает, файл не запускается.

Загрузка сначала записывается во временный `.part` в папке данных, проверяется и только затем становится доступной для установки. Перед установкой хеш проверяется ещё раз. Установка не начинается автоматически: отдельное подтверждение пользователя закрывает RouteDeck, сохраняет прежний EXE рядом с программой с суффиксом `.backup-…`, заменяет файл и запускает новую версию. При ошибке замены сохраняется или восстанавливается прежний EXE. Повышение прав не запрашивается; если папка защищена от записи, сохраните новый EXE вручную.

База, история, настройки роутера и пароль остаются в папке данных и не заменяются. Загрузка и проверка обновлений не подключаются к роутеру и не меняют его маршруты.

SHA-256 подтверждает соответствие файлу в GitHub-релизе; отдельная цифровая подпись Windows в этой сборке не добавляется.

## Для сборки следующего релиза

Увеличьте `APP_VERSION` в `version.py`, выполните `build.bat` и прикрепите `dist/RouteDeck.exe` к стабильному релизу с тегом `vX.Y.Z`. Публикуйте релиз после завершения загрузки asset; GitHub должен предоставить поле `digest` с SHA-256. Пока asset не готов или контрольная сумма отсутствует, RouteDeck откажется скачивать обновление.

Проверки:

```powershell
py -3 -m unittest discover -s tests -v
py -3 tests/run_browser_updates.py
```

Браузерные проверки обновлений используют явно тестовые ответы GitHub и временные файлы. Скриншоты в README сняты отдельно с настоящим интерфейсом и реальной проверкой публичного репозитория.
